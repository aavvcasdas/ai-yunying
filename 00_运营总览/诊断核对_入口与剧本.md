# 诊断核对：问题在「入口」还是在「剧本」？

> 2026-10-27。用户转来一份基于**封面和标题**的复盘意见（没看正片），要仓库自证。
> 这篇不是复述那份意见，是**用仓库里能实测的时间码逐条核对**它，并指出哪里成立、哪里要修正、哪里我们还缺数据。

## 〇、一句话结论

**「选题和剧本过度依赖前情」这个判断成立，而且可以用秒数证明；但「事件前置」单独做不是解药
（Day2 加更那条 0.000 秒就是事件，播放全期最低）。真正断掉的是「承诺链」——
Day0/Day1 结尾都在许下一集，Day2 之后只剩结算和投票。**

## 三、那份意见里需要修正的部分

### 1）「封面＝开头」这个前提在 Day3 上不成立

Day3 封面是「请不来 Claude，就把本鲸染成了大小姐」，但**正片第一句是"鲸鱼不是鱼"**，
染色要到 15.34 秒。也就是说：**封面承诺的事，正片 15 秒后才兑现**。
这不是"开头不够炸"，是**封面和第一句不同频**——前者卖事件，后者做科普。

### 2）「事件前置」不能单独用

Day2 加更：事件 0.000s、前 5 秒 23 字（五天最高）、无招呼词——按任何"钩子打分表"都该赢，
实际播放 3340。它的问题不在前 3 秒，在**它是通知不是事件**（"画质提升了，来选一下"），
以及**结尾没有下一个承诺**。所以：

```
留人 = 前 3 秒给事件 × 中段有行动和结果 × 结尾许诺下一集
        ↑ 我们只在第二项上稳定（每集都有事发生）
```

### 3）「2 秒跳出率高所以是开头问题」是我们自己的推断，不是数据结论

现在手上只有：播放 / 赞 / 评 / 分享 / 时长 / 以及"最近 3 条 2 秒跳出率 40%+"这一条后台提示。
**没有留存曲线本身**。2 秒跳出高既可能是第一镜不行，也可能是**推荐人群不匹配**（比如这集被推给了
从没看过的人，而开头假设观众认识角色）。这两个原因的处理方式完全相反，不能靠猜。

### 4）"换人设、删视频、堆特效"从来不在选项里

角色（鲸鱼娘高清立绘 + 大小姐 Q 版 chibi）、配音（用户提供 WAV）、字幕（Day2 加更版）、
画风都是**锁死的默认规则**（README「项目默认规则」、制作记录 §〇之十），这轮不动。
已发布的 Day3 成片按用户要求**不重渲**。

同一批素材、同一批台词，**只改顺序和取舍**——把 L03 提到前面，把 L02 的"鱼/鲸"降级成梗：

| 3.0–6.0s | L02 8.99s 的"鱼/鲸" | 「等一下……共创嘉宾，怎么变成自己了？」（原 L04）+ 一句「本鲸本来只想摸鱼」 | 把 8.99 秒的科普压到 1 句自嘲 |

代价：会损失老观众爱看的"账本细节"。所以正确做法不是改已发布的那条，而是
**把账本类内容拆成另一条**（纯复盘可以发，但它不该是拉新的主片）。

## 六、Day5 提案：一条只讲一件事的 40–60 秒

要求：**必须是真做的**（`agent.md` §0：不编数据、不假承诺），新观众零前情也能看懂，
结尾许诺下一集。两条候选，建议选 A。

### A（推荐）「本鲸给自己排了一周伙食，第一天就把预算花光了」

- **真做**：定一个真预算（比如 100 元 / 7 天），真的列菜单、真的买、真的记账，第一天就超支；
- **0–4s**：「主人给了我 100 块，让我自己排一周的饭。第一天，我就花完了。」
- **4–25s**：列菜单（画面直接给账单）→ 买 → 结账那一刻的真实数字；
- **25–45s**：剩下六天怎么办：减量 / 换成白饭 / 去找主人要（三选一由评论区定）；
- **45–55s**：结算 + 承诺：「剩下六天怎么活，你们在评论区定，明天照做。」
- 这套结构天然带**连续剧属性**（一周七集），且和"吃白饭/薄肌/抢饭"的既有梗同源，不用换人设。

### B（备选，有门槛）Day4 那套抖音黑话考卷

`Day4/Day4方案.md` 已有 16 镜约 105 秒、9 个词全部带出处。它的优点是梗密度高、易二创；
缺点是**不认识角色的新观众看不懂"为什么她在考试"**，且 105 秒超过"一条一个事件"的测试区间。
建议放 B 位，或把它剪成 45 秒的"只考 3 个词"版本先试。

## 七、发布前门禁（已落地）

```bash
# 录完音、对齐完之后，先过一遍
python3 tools/剧本/开场体检.py --json <本集 alignment.json> --event-cue L0X
```

退出码 1 就回去改稿。规则（写在脚本头部）：

1. **事件落地 ≤ 5.0s**（"事件"= 一个陌生人能听懂、且是这一集独有的动作/结果/异常）；
2. 前两句**不许**出现招呼/前情词（大家好 / 本鱼回来了 / 先统计 / 复盘 / 上一集 / 更新一下 …）；
3. 结尾**必须有下一个承诺**（下一集 / 明天 / 评论区投票 / 点菜 / 关注）。

再加四条人工问题（不看前集能不能懂）：

- 不看前几集，这条能不能看懂？
- 这一集**发生了什么之前没有的事**？
- 角色**实际做了什么**（不是说了什么）？
- 开头的承诺，结尾兑现了吗？

> 说明：`开场体检.py` 的事件位置是**半自动**（黑名单粗筛 + 允许 `--event-cue` 手动指定），
> 它只是把"吵不清的主观判断"变成"一个可复核的秒数"，最终仍要人确认。
