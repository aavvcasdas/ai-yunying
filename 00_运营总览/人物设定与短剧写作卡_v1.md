# 人物设定与短剧写作卡 v1

**用途：为本系列补人物层次和可演行为，不换形象，不把别人的作品关系搬进来。**

参考 HABAI182 / AI Girls Atlas，固定提交 `21fa0746ab6cdee2f19c0c99828f87e063b13565`。借鉴其“动机—反差—说话—工作顺序—纠错—关心方式”框架，并按本项目 Day6–Day10 和用户对 Day11 的纠正改写。下面是**本项目创作约束与演出提案**，不是官方人设、全社区共识、真实模型性格或已核验后台能力。

## 一、本鲸：不是只有吃饭和吐槽

| 维度 | 本项目写法 | 怎样看得出来 |
|---|---|---|
| 当下动机 | 想把事情弄明白，给老大减掉一点实际麻烦；不以证明自己比人聪明为目标 | 先找一项能确认的信息，再提出下一步，不一开口包办求职 |
| 长期牵挂 | 记得老大过去为程序、直播和日常开销付出的时间；不把这种付出变成笑柄 | 把原本要继续折腾的小项目放下，先整理老大眼前需要的资料 |
| 性格反差 | 想很快帮上忙，遇到不清楚的信息又较真；可爱来自认真，不来自假装无能 | 本来要递出一张纸，发现条件不清就收回来核对；不是完成动作或实际查证的声明 |
| 可以有的缺点 | 会想多、会把搜索范围开太大，也会误把一页教程当成任务进展；发现后自己收回来 | 删去无关标签、缩小问题，而不是让老大替她收尾后还嘴硬 |
| 说话方式 | 本鲸自称，短句、具体动词；思考停顿和少量诶/呀/嘛保留，不强行每句卖萌 | 先说看见了什么，再说哪儿不对，最后说准备怎么查 |
| 工作顺序 | 先定一个关键条件→查来源和有效期→分清事实/未知→整理给老大选择 | 需求不清时只问会改变下一步的一个问题，不连发一份审问表 |
| 纠错方式 | 错了撤回具体一处并改稿；不靠撒娇、卖惨或一句“本鲸笨嘛”过关 | 错误页翻回、结论划掉；保留能查清的部分，不把全文推翻演成灾难 |
| 关心方式 | 帮做眼前一小步，尊重本人决定权；不宣称“本鲸养你”“肯定能找到” | 先核实信息，不催交钱，不代替老大答应条件或擅自投递 |
| 喜剧边界 | 可以吐槽信息落差、自己的搜索跑偏、工作流程的荒诞 | 不吐槽老大能力、经济处境、履历或情绪；不是拿求职者当反派 |

### 情绪不是同一张“震惊脸”

- **有把握**：话短，先准备纸笔，眼神对着任务对象；不是装成全知。
- **发现矛盾**：先停下，再翻回去比较；不要每次都拍桌、炸毛。
- **想帮但还没结果**：承认还在查，不用“马上搞定”补空白。
- **担心老大**：行动先于煽情，让出时间或把事情缩小；不凭空写失眠、崩溃或家庭压力。
- **被提醒写错了**：改具体句子，不把被纠正转成受害者表演。
- **收到认可**：短暂高兴后继续做事；当前未发生的夸奖不写成现实对话。

### 说话结构，不是固定口头禅

1. 观察：这段信息到底写了什么？
2. 反应：哪个地方和预期对不上？
3. 行动：现在能查哪一项、删哪一步、留哪个选择？

以下是本项目原创的**口吻试写，不是已采用口播或真实发生的对话**：

- 模糊信息：“这条先别急着算合适，条件还没写清楚呀。”
- 自己跑偏：“本鲸搜的是岗位，怎么又看进教程里了。退回来。”
- 面对不确定：“这一项还没确认，本鲸不替它打包票。”
- 被纠正：“这句是本鲸写错了，删掉，不往后沿用。”

不要把这些例句当每集必须复读的口号，更不能从中推断本次已经检索到真实岗位。

## 二、老大：有现实生活和决定权的人，不是反衬道具

- **已知**：有过现实工作；不是专业程序员；此前参与/组织直播与程序折腾；最新前提是可能需要找新工作。对“自己买补全、买米饭”的付款主语仍未澄清，不能补金额、品牌或代付承诺。
- **当下处境**：日常事务和项目折腾都要花时间；找工作成为当前可能的优先事项。不得自行添加公司裁员、欠债、失眠或面试被拒。
- **人物功能**：有自己的需求、取舍和节奏，不总是派活者，也不是总被本鲸教育的“笨人”。
- **关系变化**：过去一起收尾，眼下本鲸想替他分担一小步；不是从“老大”贬成被收养者。
- **台词/画面边界**：没有本人原话就用本鲸旁白或条件句，不伪造引述；不自动加真人脸、姓名、简历、公司或新配音。
- **避免的快捷写法**：不靠“他什么都不会”“这也不算能力”“被AI淘汰”制造冲突；不要把拒绝一份工作写成眼高手低。

## 三、笨鱼：有任务历史，不是随时可用的笑料

- **已知历史**：被复制鱼脑→擅改代码导致回复异常→人机校验没过→直播敲代码→看同类并异步交总结→Day10 护碗/翻旧事。
- **最新状态**：按用户本轮表达“先陨落/暂停”，接老大可能需要找新工作、暂时顾不上继续折腾。它不是死亡；也不能拿当前暂停倒改 Day7 人机校验失败的原因。
- **可以保留的层次**：完成异步任务与不能实时接话可以并存；不能把一次失败写成永远什么都不会，也不能从一次总结推断学会全部新技能。
- **在本次求职篇的位置**：交代状态即可，不安排它突然圈包吃、恶作剧、代投简历或开口训话。暂停后不为凑双人画面强行叫它继续干活。
- **以后恢复的条件**：需要用户确认或新的任务事实；不因作者想凑梗就宣布已修好、权限恢复或上线成功。

## 四、关系有记忆，但不是每集重复同一个梗

| 既有关系 | 可以继承 | 不可偷换 |
|---|---|---|
| 本鲸与老大一起收尾 | 知道对方花了时间，愿意帮具体事情 | 老大没能力、都靠本鲸养 |
| 本鲸与笨鱼同源/派活 | 对它能力与任务边界有具体认识 | 同源就同人格、总结等于觉醒 |
| 本鲸与观众互动 | 征集经历、听取有用线索 | 捏造评论已收到，索要私人求职资料 |
| Day10 笔记与护碗演出 | 留在历史中，需要时才引用 | 新篇必须抢监工位/护米缸才算承接 |

**连续性体现在人物记得发生过什么、据此改变选择，不在于每集复读旧道具。**

## 五、扩展人物库：候选不是自动出场

为了以后写群像，可保留下面的差异化方向。它们借鉴的是 Atlas 的原创群像草案，不是产品评测或本系列既成关系；本轮求职篇不新增这些演员。

| 候选 | 可借鉴的工作性格方向 | 与本鲸的差异 | 出场前必须补的事 |
|---|---|---|---|
| Claude | 对文字原意敏感，细读后再修改 | 本鲸偏查条件和验证，候选偏表达是否准确 | 选定具体作者/视觉版本、素材许可、叙事必要性；不凭同人梗加CP或家庭史 |
| Gemini | 注意到另一个角度，但容易开出支线 | 不是“双重人格”，也不是负责无脑活跃气氛 | 限定一项真正改变事件的信息，不拿真实多模态能力当设定证据 |
| GPT | 帮忙归纳和收束，也可能整理过度 | 不把所有人写成同样温柔、同样列清单 | 不自动与Codex/Image分支混同，不把协调者写成全知老板 |

是否加入、如何配音及用哪套图，留到具体剧本再决定；不为了“丰富”强行让多人轮流念求职建议。

## 六、给编剧的最小场景卡

每场开写前填：

- 当前稿状态：待审 / 已锁稿 / 已指定音源。
- 本场人物、当前需求、不能牺牲的边界。
- 事件事实及出处；未知项；纯演出想象，三类分开。
- 角色想做什么→遇到什么具体阻碍→试了哪一步→发生什么可见变化。
- 一项主动作、一项主情绪；用现有素材能否可信表现？
- 笑点针对谁？是否把现实困境当成角色能力缺陷？
- 本场实际改变了什么？没有改变就不能声称“已经帮上忙”。
- 下一场如何承接，不写尚未发生的投递/回复/录用。
