# Live2D 模型：怎么做、能不能用 AI 生成（2026-10-29）

> 回答两件事：① Live2D 模型到底怎么改、怎么生成；② 我能不能直接生成一个。
> 结论先行：**AI 不能直接吐出 `.moc3`**（那是 Live2D Inc. 的私有二进制），但**可以生成「唯一必需的上游产物」—— 分层 PSD**，然后把 PSD 交给 Cubism Editor 或开源 psd2live 自动绑骨导出。
> 本次已经按这个流程，做了**四个原创角色**：凯 Kai / 露米 Lumi / 桃桃 Momo / 妮莉 Nelly，
> 每人一套 25–27 层素材 + 分层 PSD + 参数化预览 + 状态验收图，文件在 `tools/live2d/`。

---

## 1. 先搞清楚链路：Live2D 一共有五段

```
①原画分层 PSD ──► ②绑骨/建参（Cubism Modeler 或 psd2live） ──► ③物理与动作（physics / motion3）
        ──► ④导出 .moc3 + model3.json + 贴图 ──► ⑤运行时加载（VTube Studio / pixi-live2d-display / live2d-py）
```

| 阶段 | 唯一必需输入 | 输出 | 能否 AI/脚本生成 |
|---|---|---|---|
| ① 分层 PSD | 一张角色图 + 人工决定怎么切 | `.psd`（RGB/8bit、每部件一层、层名不重复） | ✅ **能**（本次做的就是这段） |
| ② 绑骨建参 | PSD | `.cmo3` 工程 | ⚠️ 官方靠手点；**psd2live 能自动** |
| ③ 物理/动作 | `.cmo3` | `.physics3.json` / `.motion3.json` | ✅ 可手写 JSON，也可由 psd2live 生成 |
| ④ 导出 `.moc3` | `.cmo3` | `.moc3` + `model3.json` | ❌ 必须 Cubism Editor / psd2live；**没有第三方编码器** |
| ⑤ 运行时 | `.moc3` 文件族 | 屏幕上会动的模型 | ✅ 开源运行时一堆 |

**关键认知**：`model3.json`、`physics3.json`、`motion3.json`、`exp3.json` 都是**明文 JSON，可以手写**；
只有 `.moc3` 是黑盒。所以「AI 生成 Live2D 模型」的可行边界就是：**AI 做 ①③⑤，②交给工具，④跑一次导出**。

## 2. 三条路线，按「能不能落地」排

### 路线 A：Cubism Editor（官方，最标准）

| 项 | 内容 |
|---|---|
| 费用 | FREE 版免费且**个人/年营收 1000 万日元以下的企业可商用** |
| FREE 限制（决定你够不够用） | **1 张 2048 贴图、100 个 ArtMesh、30 个参数、50 个变形器**，视频导出 720p |
| 平台 | Windows / macOS |
| 流程 | `Ctrl+O` 导入分层 PSD → 自动生成每层网格 → 拖参数 → 导出 |

**PSD 硬性要求**（导入失败基本都是这几条）：

- 格式 `.PSD`、色彩模式 **RGB**、**8bit/通道**、sRGB
- **一个部件一层**：线稿、填充、滤镜、剪贴蒙版全部合并进同一层
- **不要用图层蒙版**；不要带 Photoshop 路径信息（CC2019+ 的 path 会导致导入失败）
- 图层名不能重复（重名后期一定乱）
- 不透明度会保留，但「填充(Fill)」会按 100% 输出

> 100 个 ArtMesh 意味着 FREE 版大概够做 **上半身 Q 版**（本次 27 层远低于上限），
> 全身 + 手指 + 衣服褶皱就不够了，那时候才需要 PRO。

### 路线 B：psd2live（开源，能自动化，推荐先试）

`tsunehimatoi/psd2live` · **786★** · GPL-3.0 · 最后推送 2026-10-28 · Windows / Linux · JDK 21+

- **吃分层 PSD，自动识别图层语义 → 自动网格 → 自动变形器链 → 自动物理 → 自动待机/眨眼/点头动作**
- 直接导出 **`.cmo3`（可回 Cubism 精修）+ `.moc3` + `model3.json` + `physics3.json` + `idle.motion3.json` + 贴图**
- 还能导 VTube Studio 的 `.vtube.json`、Spine、glTF、视频、序列帧
- 自带 MCP 服务（`127.0.0.1:23871/mcp`，180+ 操作），**AI Agent 可以直接改工程**
- CLI：`gradlew -p ./psd2live run --args="--input sample.psd --output ./out --atlas 4096 --mesh-spacing 48"`

**它认图层名**（中/英/日/韩都行），所以图层千万不要乱起名：

```
face / eyedetail / eyewhite / irides / eyelash / eye close / eyebrow / nose / mouth / mouth open / mouth close
front hair / back hair / ear / headwear / neck / neckwear / topwear / bottomwear / handwear / legwear / footwear
tail / wings / objects / facedetail
侧别：-l / -r / _left / _right / 左睫毛 / 右睫毛
```

> 社区已经有人用它跑通「鲸鱼娘」：`daoming07280/whale-maid-svg-layers`（1★）——
> 59 层 SVG → 语义映射 → PSD → psd2live → **已产出 5 MB 的 moc3 + 10.2 MB 的 cmo3**。
> 这条链路是真实存在的，不是 PPT。

### 路线 C：Inochi2D / Inochi Creator（开源替代，但格式不通用）

`Inochi2D/inochi2d`（1831★）、`Inochi2D/inox2d`（301★）。能吃 PSD、能做骨骼，**但导出的是 `.inp/.inx`，不是 moc3**。
只有走 psd2live 或 Cubism 才能拿到能被 VTube Studio / 抖音直播工具读取的 moc3。
> 注：有个开源项目 `Ayatsuri2D` 号称「能打开并导出 moc3」，但我没在 GitHub 上检索到可核实仓库（0 结果），**不作为可行路线**。

### 3.4 已经验证过「能动」

每张 `sheet.png` 是 2×2 四格，全部由同一份 `rig.mjs` 在 Node 里渲染：

| 状态 | 验证的能力 |
|---|---|
| idle | 中立姿态基线 |
| turn + blink | **转头时五官相对脸部错位（视差）** + 闭眼层淡入 |
| talk + sway | **张嘴差分（纵向展开）+ 头发/尾巴摆动** |

六个滑块 + 自动眨眼 / 呼吸 / 头发尾巴摆动 / 说话口型四个开关，底部实时列出当前模型的图层。

## 4. 诚实说明：这版的边界

| 做到了 | 没做到 |
|---|---|
| 四个**原创**角色（只对物种特征取意，不描图），配色/设定自持 | **没有 `.moc3`** —— 私有格式，必须跑一次 Cubism 或 psd2live（沙箱无 JDK） |
| 符合 Cubism 导入规范的分层 PSD（RGB/8bit/每部件一层/层名唯一/无蒙版） | 不是正式美术资产：这版是**矢量示意稿**，笔触比真立绘简单 |
| 图层名落在 psd2live 语义词表内，丢进去可自动绑骨 | 没有真正的多轴变形器（现在是位移/旋转/缩放近似），不能替代绑骨 |
| 参数驱动预览 + 四状态离线验收图，四角色一遍出 | 没有手臂骨骼、没有衣服摆动、没有半身以下 |

**换句话说**：这是一条**已经打通的管线 + 四套合规素材**，不直接是能上播的成品模型。

## 6. 一句话回答「你能生成吗」

**能生成它上游最值钱的那一半（分层 PSD + 参数化预览 + 验收图），并且这次一口气生成四个原创角色；
不能生成 `.moc3` 本体**，因为那是只由 Cubism Editor / psd2live 产出的私有格式，
任何声称「AI 直接生成 moc3」的说法都得先怀疑。
