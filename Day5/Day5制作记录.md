## 二之三、配音怎么对上的（本轮核心）

**配音**：`day5.wav`（用户在 `main` 分支上传，100.26s）。取法：

```bash
git show origin/main:day5.wav > day5.wav     # 16.0 MB；本分支不重复入库（.gitignore 已挡）
```

**对齐做法（v3 改成段级，不再靠字数推时间）**：

上一版（v2）是「在时间轴上按字数占比找边界，再吸到能量谷」，它有两个毛病：

1. 边界会落到**长停顿中间**：例 L11「诶？」真声音在 23.36–23.99，旧表给的 cue 是 22.64–22.92 ——
   字幕在**静音里**就弹出来，声音到的时候已经换屏；
2. 句内按字数铺的做法，平均首字晚 0.166s、最坏 0.99s（L19「读一次，等一次。」整句晚 1 秒），
   采样 2006 帧里 6.8% 的帧挂的是上一句。

v3 换成**段级分配**（`tools/day5制作/align_day5_segments.py`）：

1. 10ms RMS 包络 → 发声段（−45dB 相对 / −50dB 绝对），本片 **51 段 / 50 条缝 / 有声 76.63s**；
2. 51 段要分给 40 句 → 必然有 **11 处句内气口**（长句换气，例 L01、L05、L09、L15、L27、L30、L39）；
3. DP 分配：代价 =（该句有声时长 / 字数÷全片语速）² + 0.35×(组内段数−1−该句标点数)² − 0.06×边界停顿时长，
   即「时长要和字数对得上」「没逗号的句子不许乱断」「长停顿更像句界」；
4. **每句起点就是它第一个发声段的起点，终点就是最后一个发声段的终点** ——
   句界必然落在静音里，结构上不可能抢在声音前面上屏。

**自检结果**：

| 指标 | 值 |
|---|---|
| 句首=首段起点 / 句尾=末段终点 | **40/40、40/40** |
| 句内气口（允许多段一句） | 11 处，全部落在真静音缝里 |
| 有声总时长 | 76.63s / 100.26s（76.4%） |
| 字/秒（含句间静音） | 中位 4.36，**不要拿它当验收**：短惊叹句（「诶？」0.83）和拖长音句（「本鲸说，这叫本鲸养鲸鲸。」2.22）天然偏离 |

> 为什么片长 103.9s：配音是**慢而认真**的版本，按实测走。
> **没有为了贴估算去加速配音**——那种做法会把呆萌感削掉。

## 二之四、字幕怎么对上的（用户反馈「字幕没有对上」之后）

### 病在哪（诊断过，不是猜）

用 v2 的 `chars_timed` 复算 57 屏，再按 30fps 采样 2006 帧：

| 指标 | v2（旧） | v3（现在） |
|---|---:|---:|
| 平均首字延迟（字幕比声音早/晚上屏） | 晚 **0.166s**，最坏 **0.99s**（L19「读一次，等一次。」整句晚 1 秒） | 0（屏起点=发声段起点） |
| 末字平均提前消失 | **0.183s** | 0（屏终点=发声段终点） |
| 采样帧里挂错句的比例 | **6.8%** | 0（逐屏核对 47/47） |
| 换屏点落在静音里（字幕在无声时弹） | 有（L11「诶？」提前 0.7s，声音还没出来字幕就没了） | 0 |

根因：v2 是**用字数推屏级时间**（`SUB.clauses(…, chars, …)`），再从推出来的位置找最近的谷。
只要语速有起伏（拖长音、抢读短句），误差就攒成 0.2–1.0s。

### v3 的做法

1. `build_subtitle_timing.py`：**一屏 = 一段连续发声**（51 段发声 → 47 屏，短分句按标点合进同段）；
2. 分句只决定「这一段显示哪几个字」，**不参与计时**；分句数少于段数时**不切字**，
   一屏跨过换气口（人还在说话，观众看不出来），保证一个字都不改、不丢；
3. `render_day5.mjs` 加 `--subs`：优先用实测屏；**上一屏一直挂到下一屏上屏**（气口不空屏），
   末屏挂到片尾卡 100.56s 才撤。

| 验收项 | 做法 | 结果 |
|---|---|---|
| 换屏时刻对不对 | 从 v3 成片里把字幕条（y 975–1115）按 30fps 抽成 3116 帧，逐帧算差分找换屏点 | 正片内检出 **46 次换屏**（首屏 0.00s 起，不需要动画），与时间轴 **46/46 对上**，最大偏差 **30ms**（= 30fps 一帧） |
| 有没有空屏 | 同上，跟「肯定没字幕」的片尾卡帧比 | **0 帧空屏**（含 0.21–1.39s 的句间气口） |
| 会不会在静音里弹字幕 | 取成片音轨，看每个上屏点前 100ms 是否静音、上屏后 0.15s 内是否有声 | **47/47 强边界**（前静音 + 上屏即有声），**0 屏起在静音里** |
| 音画有没有偏移 | 成片音轨首个发声 0.05s、末个 100.26s | 与配音文件一致，**mux 无偏移** |

> 顺带：`Day5/day5_voice_alignment.json` 已经是段级版本（带每句的 `segments` 列表），
> 旧的 `align_day5_voice.py`（字数占比版）**已删除**，别再用它复算。

## 五、命令备忘

```bash
# 11 镜检查帧（改一点看一点，不要等成片）
node tools/day5制作/render_day5.mjs --stills

# 指定秒数出帧（改完某个镜先验这一秒）
node tools/day5制作/render_day5.mjs --times 12.5,33.2,82 --tag chk

# 无配音样片（本轮产物，默认就是 Day3 立绘）
node tools/day5制作/render_day5.mjs --out "Day5/成片/无配音样片/day5_无配音样片_v3_Day3形象.mp4"

# 出老版对照帧（只在需要对比时用）
node tools/day5制作/render_day5.mjs --char ss2 --times 4.67 --tag old

# ① 取配音（用户放在 main 分支；本分支不入库）
git show origin/main:day5.wav > day5.wav

# ② 句级对齐：发声段成组分给 40 句（每句起止=段起止）
python3 tools/day5制作/align_day5_segments.py

# ③ 屏级字幕：一屏=一段连续发声
python3 tools/day5制作/build_subtitle_timing.py

# ④ 出成片
node tools/day5制作/render_day5.mjs --cues Day5/day5_voice_alignment.json \
  --subs Day5/day5_subtitle_timing.json --audio day5.wav \
  --out "Day5/成片/样片/day5_配音对齐_v3_字幕对齐.mp4"

# ⑤ 验字幕（从成片里抽字幕条逐帧找换屏点）
python3 tools/day5制作/check_subtitle_sync.py "Day5/成片/样片/day5_配音对齐_v3_字幕对齐.mp4" \
  --subs Day5/day5_subtitle_timing.json
# 期望最后一行：结论：字幕与配音对齐 ✓
```

> 依赖：`@napi-rs/canvas` + `@ffmpeg-installer/ffmpeg`，脚本会从 `/tmp/node_render/node_modules` 兜底找；
> 新环境先 `mkdir -p /tmp/node_render && cd /tmp/node_render && npm i @napi-rs/canvas @ffmpeg-installer/ffmpeg`。
